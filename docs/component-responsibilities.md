# ContentArea / TodoList 責務分割方針

更新日: 2026-09-04

## 現在の境界

- `App.vue` は `VITE_BACKEND_URL` を正規化し、設定済みの場合だけ API クライアントを生成する。
- `ContentArea.vue` はページ見出しと設定ゲートを担当する。URL 未設定時は解決手順だけを表示し、タスク状態を持たず、API を呼ばない。
- `TodoList.vue` は設定済み API クライアントを受け取り、一覧取得・追加・完了切替・タイトル編集・削除と、その処理中／成功／失敗表示を担当する。環境変数やページ全体のレイアウトは扱わない。

## 次に分割する条件と手順

`TodoList.vue` に別のタスク操作を追加するとき、同じ変更で次の順に分割する。今回の整理では挙動を変える不要なリファクタリングは行わない。

1. 入力欄を `TaskCapture.vue` に分け、`title` と `busy` を props、作成要求を event にする。
2. フィルター・件数・行一覧を `TaskCollection.vue` に分け、tasks と操作中状態を props、更新・完了切替・編集・削除要求を event にする。
3. API 呼び出し順序と通知状態は `TodoList.vue` に残し、子コンポーネントを調停する役割に限定する。
4. `ContentArea.vue` のテストは設定ゲートだけ、`TodoList.vue` のテストは API 呼び出し順序だけ、子コンポーネントのテストは表示と event だけを検証する。

この境界により、設定不足時にタスク UI が誤って復活することと、画面枠へ API 処理が漏れることを防ぐ。
